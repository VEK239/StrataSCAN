# StrataSCAN 0.2.2 synthetic robustness and scalability rerun plan

## Objective

Produce two immutable, current-release packages derived from the established
seven-family synthetic benchmark shown in the algorithm-comparison grid. They
support two distinct claims without pooling them:

1. **Robustness:** performance across geometry, dimension, uniform-background
   fraction, generated-data seed, and sample size through 200,000 points.
2. **Scalability:** monitored quality, runtime, memory, and failure behavior
   from 500,000 through 5,000,000 points.

Both packages evaluate the released `StrataSCAN` 0.2.2 defaults at the exact
commit recorded in their manifests. They retain every timeout, memory limit,
and numerical error as a benchmark outcome; no failed run is silently retried
with different settings or excluded from a denominator.

## Frozen dataset matrix

Use the seven fixed conditions from
`benchmarks/protocol.full-legacy-grid-7synthetic.json`, which are the rows in
the original comparison figure:

| ID | Family | Dimension | Uniform background |
|---|---|---:|---:|
| `multidensity_2d` | Multidensity | 2 | 75% |
| `ultrasparse_16d` | Ultrasparse | 16 | 95% |
| `overlapping_density_16d` | Overlapping density | 16 | 80% |
| `moons_2d` | Moons | 2 | 25% |
| `rings_2d` | Rings | 2 | 75% |
| `overlap_8d` | Gaussian overlap | 8 | 25% |
| `imbalanced_16d` | Gaussian imbalance | 16 | 75% |

Use generated-data seeds `23, 42, 73, 101, 151` for every small-size cell.
The seed identifies the generated dataset, not an independent biological
replicate.

| Tier | Sizes | Data seeds per condition | Purpose |
|---|---:|---:|---|
| Robustness | 5k, 20k, 50k, 100k, 200k | 5 | Variation over geometry, background, size, and data generation |
| Scaling replication | 500k, 1M | 2 (`42`, `151`) | Detect obvious seed-dependent scaling failures |
| Scaling endpoint | 2M, 5M | 1 (`42`) | Establish monitored practical boundary |

This is a fresh single-manifest rerun. Older measurements remain lineage
evidence only and will not be merged into this package.

## Frozen method matrix

Run the nine methods shown in the established comparison figure, with their
unchanged controlled reference profiles. The benchmark uses identical
dataset/seed cells for every method, including deterministic methods, so paired
seed-level comparisons remain available.

- Baselines: `DBSCAN`, `HDBSCAN`, `OPTICS`, `SNN-DBSCAN`, `VDBSCAN-2007`,
  `AMD-DBSCAN`, `kNN-DBSCAN`, and `kNN+Leiden`.
- Released method: `StrataSCAN`.

This is intentionally a full rerun. Older baseline records remain useful
lineage evidence, but a single current manifest avoids mixing result layouts,
hardware generations, and algorithm versions.

### Nested ablation study

Add a predeclared, separately manifested mechanism study within the same
seven-family benchmark. It does not change the headline external comparison:
each ablation is compared with the released method on identical generated
datasets, while baselines remain in the primary nine-method matrix.

Use these representative cases:

- `multidensity_2d`: variable-density separation in 2D;
- `ultrasparse_16d`: high-dimensional sparse signal;
- `overlapping_density_16d`: overlapping density levels, the known semantic
  rate-gap limitation;
- `moons_2d`: non-convex geometry; and
- `overlap_8d`: high-dimensional Gaussian overlap.

For each case, run `StrataSCAN`, `StrataSCAN-FixedComponentBound`,
`StrataSCAN-ContinuousBackground`, `StrataSCAN-RateChangepoint`, and
`StrataSCAN-WideGraph` at 5k, 50k, and 200k using the five robustness seeds.
The release rows are intentionally rerun under the ablation manifest so every
paired comparison has one self-contained provenance record. No ablation is
scheduled above 200k: the scaling panel evaluates the released algorithm and
external comparators, not internal mechanism variants.

The older 12-condition noise/ablation sweep remains supplementary lineage
evidence. It must not be pooled with this locked seven-family study.

## Job count and execution phases

The primary benchmark contains 1,953 jobs. The separate ablation package adds
375 jobs, for 2,328 benchmark executions in the full plan:

| Phase | Formula | Jobs |
|---|---:|---:|
| Robustness, all 9 methods | 7 conditions x 5 sizes x 5 seeds x 9 methods | 1,575 |
| Scaling replication, all 9 methods | 7 x 2 sizes x 2 seeds x 9 | 252 |
| Scaling endpoint, all 9 methods | 7 x 2 sizes x 1 seed x 9 | 126 |
| Nested ablations, released method plus four controls | 5 cases x 3 sizes x 5 seeds x 5 methods | 375 |
| **Total** |  | **2,328** |

Create and freeze four versioned protocols before execution: a seven-family
robustness matrix, a two-seed scaling-replication matrix, a one-seed endpoint
scaling matrix, and the five-case five-method ablation matrix. The split is
necessary because the runner freezes one seed set per size tier. Run each
protocol only in its own output directory, always resuming that directory:

1. 5k/20k smoke: one condition, five seeds, all primary methods and controls;
   verify the manifest,
   resource recording, and output hashes before substantial compute.
2. Complete 5k--50k, then 100k--200k. Do not inspect aggregate ranks to alter
   method parameters.
3. Complete 500k and 1M before scheduling 2M and 5M.
4. Complete 2M and then 5M. A method that exceeds the fixed resource cap
   remains a recorded failure; it does not block other pending jobs.

## Fixed resource and reproducibility controls

- One worker per job; do not use parallel jobs on the same host for resource
  comparisons.
- Initial cap: 1,200 seconds and 8,192 MiB per job, matching the existing
  locked v0.2.2 evidence protocol. Record any later approved cap change as a
  new protocol version, never as an in-place edit.
- Capture commit SHA, dirty state, package versions, machine details, input
  hashes, protocol hash, stdout/stderr, and peak process RSS in the manifest.
- Use a new ignored run directory, for example
  `results/runs/v0.2.2-synthetic-robustness-scaling-v1`; never overwrite prior
  runs. Commit only curated tables, figures, a manifest digest, and a concise
  evidence report under `results/published/`.
- Execute `validation.json` after every resumed batch. It must have no missing,
  duplicate, malformed, or unexpected job IDs before analysis begins.

## Analysis plan

Report primary quality (`macro_target_f1`) together with noise F1, pairwise
F1, fragmentation, merging, spurious background-majority clusters, runtime,
peak RSS, and failure status. The target-background-structure score may appear
only as a clearly labelled post-hoc diagnostic; it is not the headline endpoint
for this legacy synthetic suite.

Keep the following views separate:

- median/IQR and deterministic bootstrap intervals over the five generated-data
  seeds through 200k;
- every paired seed-level StrataSCAN-minus-method delta, including reversals;
- log-log runtime and RSS by family and size, with 500k/1M seed replication
  shown individually;
- success/failure frontier by method, size, family, and resource-limit reason;

For each nested control, report every paired seed-level delta from released
`StrataSCAN`, the distribution across the five seeds, and the sign/reversal
count. These are single-component comparisons, not evidence that the full
algorithm is globally optimal. Analyze the older 12-condition ablation sweep
separately, if it is included at all; never use it to select a method or modify
this locked matrix.

No method ranking may be selected after examining this matrix. Any new tuning,
family, resource limit, or baseline profile requires a separately named
follow-up protocol.

## Completion gate

The rerun is complete only when the primary package has all 1,953 expected job
records and the ablation package has all 375 expected job records, both
structurally valid. The final report must explicitly distinguish:

- quality robustness through 200k with five seeds;
- replicated scaling through 1M;
- single-seed endpoint scalability through 5M; and
- nested mechanism ablations through 200k; and
- failures as observed algorithm/resource outcomes.
