# StrataSCAN 0.2.0: optimization research plan

Status: historical design and development plan for the algorithm subsequently
released as StrataSCAN 0.2.0. The 0.1.2 algorithm and evidence remain frozen at
Git tag `v0.1.2`. See
[`results/published/v0.2.0/RESULTS.md`](../results/published/v0.2.0/RESULTS.md)
for the release decision, fixed defaults, and limitations. The dev10 and dev9
reports preserve the earlier candidate and scaling evidence.

Target venue: [OEDM 2026](https://fan-meng.github.io/ICDM-Workshop/OEDM-26/index.html),
the IEEE ICDM Workshop on Optimization Based Techniques for Emerging Data
Mining Problems. The workshop explicitly covers combinatorial, nonconvex,
large-scale, stochastic, and graph optimization. Its paper deadline is
2026-08-20 AOE.

## Non-negotiable algorithm properties

The 0.2.0 optimization must preserve the two defining practical properties of
StrataSCAN:

1. **Noise is a first-class decision.** The feasible set must include leaving
   any vertex as background, including the all-background solution. No cleanup
   pass may be responsible for repairing forced cluster assignments. The
   objective must penalize background bridges and unsupported micro-clusters
   directly.
2. **Millions of points are a production target.** The production path may use
   only sparse bounded-degree graphs, array/CSR-like storage, chunked cost
   construction, and `O(|V| + |E|)` working memory. Exact mathematical
   programming is a reference solver for small instances, never a dependency
   of the million-point path.

Every proposed model or solver change must be rejected if it improves the
formal objective while materially breaking either property.

The 0.2.0 line also has an **inheritance contract** with 0.1.2:

- a sparse `k`-nearest-neighbour graph remains the only geometric primitive;
- multiscale neighbour-shell volumes remain the observations fitted by the
  constrained Gamma mixture;
- density strata and an explicit background process remain the statistical
  representation;
- strict core points and their induced `k`-NN connected components remain the
  source of cluster identities;
- non-core points may attach only through existing graph neighbours, otherwise
  they remain noise.

The optimization layer may select the supported strata, core radii, and
border/noise decisions. It must not replace StrataSCAN with embedding learning,
a dense affinity matrix, or an unconstrained generic graph partitioner.

## 1. Why 0.1.2 is not yet an optimization paper

The 0.1.2 stratification stage already maximizes the likelihood of a
constrained multiscale Gamma mixture and selects mixture complexity by
held-out likelihood. The final clustering stage, however, is a sequence of
local decisions:

- `q95(d4)` selects dense cores;
- the lowest 2% of `d4 / d32`, 49 null windows, and `p < 0.05` activate a tail;
- `q5(d4)` selects tail cores;
- `1.25 * epsilon` assigns border points;
- components smaller than five points are removed.

These decisions are individually interpretable but do not minimize one global
criterion. They also make dense and sparse clusters separate code paths.

## 2. Proposed 0.2.0 problem

The primary proposal is **MDL-calibrated StrictCore optimization**. It keeps the
0.1.2 representation and optimizes its currently hand-selected decisions.

Let `G_k = (V, E_k)` be the sparse `k`-NN graph, `v_i` the vector of shell
volumes for point `i`, and `r_is` its posterior responsibility for Gamma
stratum `s`. Let `d_i^core` be the current strict-core neighbour distance
(`d4` in 0.1.2).

The decision variables are:

- `u_s in {0, 1}`: whether density stratum `s` is supported;
- `t_s`: an index into the sorted observed `d_i^core` values of stratum `s`;
  this selects `epsilon_s` without a hand-written quantile grid;
- `c_i in {0, 1}`: whether point `i` is a strict core point;
- `b_ij in {0, 1}`: whether non-core point `i` attaches to core neighbour `j`;
- `o_i in {0, 1}`: whether point `i` remains noise;
- `theta`: the constrained Gamma density/background model and predictive edge
  attachment model.

The strict-core structure is retained as a constraint, not merely encouraged:

```text
c_i = 1  iff  u_s(i) = 1 and d_i^core <= epsilon_s(i)
sum_(j in N_k(i)) b_ij + o_i = 1 - c_i
b_ij <= c_j
b_ij = 0 when (i, j) is not an existing k-NN edge.
```

Cluster identities are the connected components of the induced graph on
`c_i = 1`, using the same strict core neighbour edges as 0.1.2. Border
variables may assign a non-core point to one of those components; unassigned
points are noise. The optimizer never creates a geometric edge that is absent
from the `k`-NN graph.

The objective is

```text
minimize over (u, t, c, b, o, theta)

    sum_i L_shell(i, c_i, o_i; theta)
  + sum_(i,j) in E_k b_ij * L_attach(i, j; theta)
  + L_topology(core connected components; G_k, theta)
  + L_MDL(theta, u, t, core connected components).
```

All terms are measured in nats:

- `L_shell` uses the complete signal-versus-background log likelihood from the
  multiscale Gamma mixture, rather than thresholding its posterior;
- `L_attach` is the predictive code length of attaching a border point through
  a locally normalized `k`-NN edge;
- `L_topology` compares the observed mutual-rank/connectivity evidence with the
  fitted background graph process;
- `L_MDL` pays for Gamma components, supported strata, selected core radii, and
  output components.

A BIC code is an acceptable reference implementation; a blocked prequential or
universal code is the desired paper version. Because every term uses the same
information unit, there is no free weighted sum of coverage, separation, and
stability scores.

## 3. Statistical model and optimization loop

Use block-coordinate descent with a monotone objective trace:

1. Build the `k`-NN graph and the same multiscale shell volumes as 0.1.2.
2. Fit one explicit background process plus constrained signal Gamma profiles.
3. Convert shell and neighbour evidence into core, noise, and attachment code
   lengths.
4. Sweep each stratum's sorted core-distance events with incremental union-find
   updates and select the radius that gives the largest objective decrease.
5. Given the core components, solve border-versus-noise assignment independently
   over the existing sparse neighbour lists.
6. Refit `theta` from the current solution.
7. Accept a split, merge, graph scale, or model update only when it reduces
   total description length.
8. Stop when a full deterministic sweep makes no discrete objective
   improvement.

For small graphs, enumerate or formulate the discrete threshold/assignment
problem exactly and report the optimality gap. For large graphs, use a sparse
event-sweep solver:

1. construct shell and edge code lengths in chunks;
2. sort/merge activation events per stratum;
3. update core components incrementally with union-find;
4. solve border/noise choices from bounded neighbour lists;
5. process independent strata/regions in parallel where cross-stratum edges do
   not couple the objective;
6. stream diagnostics without materializing dense pairwise matrices.

Every accepted large-scale move must decrease the same objective. The exact
solver supplies a ground truth for measuring the coordinate solver's gap; it
is not the production path.

The important unification is that there is no tail branch. A sparse coherent
component is selected when its Gamma shell evidence and induced `k`-NN
topology outweigh its background and description costs. Isolated background
points remain unselected.

## 4. Removing the current magic numbers

| 0.1.2 choice | 0.2.0 replacement |
| --- | --- |
| `k = 32` | Keep `k = 32` in the first optimization experiment to isolate the new extraction objective. Only then compare MDL selection over nested `k`-NN graphs; the representation remains a `k`-NN graph. |
| Shell ranks `(4, 8, 16, 32)` | Keep these shells in the first experiment. Later offer nested/dyadic shell candidates and retain breakpoints by MDL while preserving shell-volume Gamma modeling. |
| Mixture components `2..8` | Start with one background component and split/merge signal components while `Delta MDL < 0`; no statistical maximum component count. |
| Three 80/20 holdouts | Prequential or blocked predictive code. Sampling count becomes an accuracy/resource control, not a decision threshold. |
| Minimum component mass `0.005` and assignment stability `0.80` | Delete components that fail to repay their description length. Report perturbation stability as evidence, not as a gate. |
| Tail mass `0.20`, dense mass `0.01`, largest rate gap | Use an explicit background likelihood inside the joint objective. |
| Posterior threshold `0.50` | Use the complete log odds as a unary cost; do not threshold before optimization. |
| Dense `q95` and tail `q5` | Select one observed core-distance event per Gamma stratum by the global MDL objective; no quantile grid. |
| Tail probe `2%`, 49 windows, `p < 0.05` | Remove the hypothesis-test branch. If an application requires an error rate, expose FDR as an application-level risk constraint rather than an algorithm default. |
| `min_samples = 5`, `min_cluster_size = 5` | Keep strict-core connectivity, but use component description cost and local graph evidence instead of deleting components at a fixed size. |
| Border multiplier `1.25` | Keep border assignment through `k`-NN core neighbours, but choose attach versus noise by predictive edge code length. |
| Seed `42` | Deterministic initialization and stable hashes; seeds remain only for explicit perturbation experiments. |
| Fit cap `10,000` | Select a coreset to a requested approximation/error budget and report that budget. |
| Fixed iteration limits and tolerances | Treat them as numerical solver controls and stop by relative primal/dual gap or monotone discrete improvement. |

The goal is not literally zero constants. Model assumptions, numerical
tolerances, and resource budgets must remain. The rule is that every exposed
number has one of three roles: a derived statistical quantity, a numerical
accuracy target, or a user-declared resource/risk budget. No quality-critical
number should be a benchmark-tuned default.

## 5. First implementation slices

### Slice A: objective and exact reference

- Freeze `k = 32`, shells `(4, 8, 16, 32)`, and the fitted 0.1.2 Gamma model.
- Add typed shell/topology/attachment code structures and a pure objective
  evaluator.
- Implement exact enumeration of per-stratum core-distance events plus
  border/noise choices on tiny induced graphs.
- Test strict-core feasibility, objective accounting, and equality to
  brute-force optima.

### Slice B: scalable solver

- Add deterministic sorted-event sweeps, incremental union-find, and
  border/noise updates on bounded neighbour lists.
- Require a non-increasing objective trace.
- Compare the heuristic with exact optima on small graphs and report gaps.
- Require `O(|V| + |E|)` memory, chunked cost construction, and near-linear
  empirical time scaling; forbid dense `n x n` state.
- Add resume/checkpoint support so a long million-point solve does not have to
  restart after interruption.

### Slice C: data-driven costs

- Replace fixed core quantiles with optimized observed-distance events driven
  by Gamma likelihood ratios and topology code length.
- Fit same-cluster versus boundary edge likelihoods without labels, using
  blocked predictive coding and the strict-core components.
- Add split/merge MDL component selection and explicit background modeling.

### Slice D: adaptive graph scales

- Compare the frozen 32-neighbour/four-shell representation with MDL-selected
  nested `k` and shell candidates.
- Keep `k`-NN geometry and Gamma shell modeling in every variant; this slice
  selects their scale, not a different representation.

## 6. Evaluation and paper claims

The paper should make four claims, each with a direct experiment:

1. **Global formulation:** Gamma-stratum support, strict core radii, border
   assignments, and noise minimize one explicit graph objective. Show exact
   solutions and optimality gaps on small instances.
2. **Calibration without labels:** no benchmark annotations select runtime
   thresholds. Show that label-free MDL choices track useful operating points.
3. **Unified variable-density behavior:** dense and sparse clusters use the
   same optimization. Include cases that currently trigger the special tail
   branch and the rare large failure flips documented for 0.1.2.
4. **Scalability:** the large-graph solver monotonically reduces the objective
   and preserves the existing synthetic, cytometry, Samusik, and Gaia scope.

Required baselines and ablations:

- frozen StrataSCAN 0.1.2;
- Gamma likelihood plus the old StrictCore extraction;
- optimized core radii without topology terms;
- optimized StrictCore extraction without MDL;
- exact versus scalable solver on small graphs;
- fixed versus adaptive graph scales;
- HDBSCAN, DBSCAN, OPTICS, Leiden, and the existing benchmark methods where
  their resource requirements permit.

Primary unsupervised results must report objective value, description length,
perturbation stability, runtime, memory, and optimality/relaxation gap. External
labels remain evaluation only and must never select defaults.

Noise behavior must additionally report signal/background precision-recall,
background leakage into clusters, the mass of unsupported micro-clusters, and
the rate of cluster merging through background bridges. Scaling experiments
must retain the frozen 0.1.2 sequence through five million observations and
record graph construction, cost construction, optimization, and peak memory
separately.

## 7. Release gates

These were the original prospective release gates. The 0.2.0 release decision
fixed the primary configuration before every follow-up benchmark was complete;
the release record explicitly identifies the remaining validation as pending.

- all 0.1.2 tests and frozen evidence remain reproducible from `v0.1.2`;
- the exact StrictCore objective passes brute-force tests on tiny graphs;
- the scalable solver has a monotone objective trace and a measured small-graph
  gap;
- the production path has sparse `O(|V| + |E|)` memory, supports chunked cost
  construction, and completes the prespecified five-million-point benchmark;
- the optimizer can leave arbitrary vertices as background and does not rely
  on post-hoc noise cleanup;
- no dense/tail quantile, p-value, minimum cluster size, or border multiplier
  is required by the 0.2.0 default path;
- all parameter selection is label-free;
- the full prespecified benchmark matrix is frozen before inspecting final
  aggregate scores.
