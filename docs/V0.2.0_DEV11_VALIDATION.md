# StrataSCAN 0.2.0-dev11 validation note

Status: experimental infrastructure and negative/diagnostic evidence. Dev11 is
not a promotion candidate. The public `StrataSCAN` alias remains frozen at
0.1.2, and the locked dev10 results are not reused to choose this design.

## Why dev11 exists

The locked dev10 ICL search selected the configured maximum of eight Gamma
components in 10 of 14 runs. Expanding a development search to 16 moved several
optima upward and left some at the new boundary. This showed that the Gamma
component count was partly measuring the resolution needed to approximate a
heterogeneous background, rather than only the number of meaningful density
strata.

Dev11 separates three concepts in diagnostics and validation output:

1. **Gamma density bases**, which approximate the shell-volume distribution;
2. **semantic signal strata**, which are allowed to seed ordinary StrictCore
   extraction;
3. **background bases**, which share one operational background group.

The count in item 1 is no longer reported as the number of strata.

## Implemented experimental changes

### Adaptive, warm-started Gamma basis search

The search starts at `max_components=8`. If the best semantic ICL score lies
within `boundary_margin=1` of the current bound, it expands by four components,
up to `hard_max_components=24`. Every added candidate receives a deterministic
split warm start from the previous fit as well as independent initializations.
Diagnostics report every evaluated bound, whether the hard bound was reached,
and convergence for every candidate.

The semantic ICL entropy is computed after all background bases have been
aggregated into one background state. The likelihood and parameter penalty
still charge for every fitted Gamma basis parameter; ambiguity among nuisance
background bases is not treated as ambiguity between scientific strata.

### Component-role experiments

The validation driver exposes four role assignments:

- `largest_rate_gap`: the dev10-compatible dense-prefix split, now combined
  with adaptive/warm basis fitting;
- `rate_changepoint_mdl`: an uncertainty-standardized adjacent log-rate change
  point that can retain an all-background solution;
- `background_scan_mdl`: promote a basis only when it passes the coded dyadic
  background scan;
- `validated_rate_prefix`: propose a contiguous rate prefix and validate its
  connectedness against equal-width rank windows.

Only `largest_rate_gap` is the current dev11 default. The other assignments are
controls: early validation found that the coded model is too conservative and
that the lighter prefix validation does not control all nulls.

### Alternative background distribution

`background_distribution="gamma_rate_mixture"` fits one explicit background
state with a point-specific latent Poisson rate

```text
lambda_i ~ Gamma(alpha, beta)
shell_ij | lambda_i ~ Gamma(shape_j,
                            rate=lambda_i * rank_j**slope).
```

Integrating `lambda_i` produces a heavy-tailed multiscale background density.
It can represent a continuum of background intensities without discretizing
that continuum into semantic strata. Fixed-rate Gamma profiles remain the
signal components because the Gamma shell law follows directly from the local
Poisson model.

This alternative is deliberately not the default. In the first pilot it often
absorbed true signal along with background, demonstrating that a more flexible
background likelihood cannot by itself identify which density modes are
scientific clusters. Topological evidence or a constrained background geometry
is still necessary.

## Development pilot

The reproducible driver is `scripts/validate_optimization_dev11.py`. The first
broad run used all seven synthetic families, `n=1,000`, development seed 23,
one numerical initialization, initial bound 8, hard bound 16, and uniform-noise
nulls in 2, 8, and 16 dimensions. These settings are a fast screen, not release
evidence.

| Model | Mean synthetic macro F1 | Mean pairwise F1 | Mean noise F1 | Hard-bound rate | Uniform-null false-signal rate | Uniform-null false-cluster rate |
|---|---:|---:|---:|---:|---:|---:|
| dev10 fixed largest gap | 0.6974 | 0.6699 | 0.8427 | 0.80 | 1.00 | 1.00 |
| adaptive largest gap | 0.7060 | 0.6520 | 0.8658 | 0.40 | 1.00 | 1.00 |
| adaptive coded background | 0.0450 | 0.0560 | 0.7069 | 0.40 | 0.00 | 0.00 |
| continuous-rate background | 0.2786 | 0.0650 | 0.5633 | 0.00 | 0.33 | 0.00 |

The adaptive search reduced boundary saturation and slightly improved mean
macro/noise F1, but reduced pairwise F1 and still treated every uniform null as
containing a signal stratum and cluster. The coded role model controlled all
three nulls but removed too much real signal. The continuous-rate background
avoided a finite-component ceiling but underfit cluster identities.

The selected candidate failed the numerical convergence flag in one of ten
adaptive-largest-gap conditions in this one-restart screen. Production-like
three-restart checks are required before interpreting this as a solver defect.

Raw evidence is in
`results/runs/optimization_dev11_development_n1000_seed23/`.

## Interpretation

Raising the component cap was a useful diagnostic but is not a sufficient
algorithmic fix. The main unresolved problem is semantic identifiability:
local shell density alone cannot reliably distinguish a meaningful cluster
from boundary-induced or continuously varying background density. A very broad
background law controls component proliferation by absorbing signal; a narrow
background law preserves signal by discretizing the null into false strata.

The next formulation should therefore make the background geometry part of the
same objective. Candidate directions are:

1. calibrate component support on fresh homogeneous and inhomogeneous Cox-process
   nulls over sample size and dimension;
2. include a boundary-aware accessible-volume model, because bounded uniform
   samples currently create artificial interior/boundary density modes;
3. compare Gamma-rate and lognormal-rate Cox backgrounds while retaining the
   conditional Gamma shell law;
4. use disjoint neighbour windows for density fitting, semantic-role evidence,
   and final extraction so evidence is not counted twice;
5. require an interior component optimum, zero false clusters on the null suite,
   and non-inferior synthetic/real-data quality before changing the default role
   model or public estimator.

Fresh validation seeds are required after the formulation is revised. The
dev10 locked seeds remain audit evidence only.
