# StrataSCAN 0.2.4 optimizer impact audit

Status: final read-only evidence audit for the 0.2.4 optimizer correction  
Scope: `src/stratascan/optimization.py` and `tests/test_optimization.py`  
Decision: do not treat affected 0.2.3 optimizer results as canonical 0.2.4 evidence

## Corrected semantics

The optimizer now evaluates only realizable inclusive core-distance thresholds:

\[
V_s(t)=\{i\in V_s:d_i\le t\},
\]

where `t` ranges over distinct observed core distances. A prefix ending inside an
exact distance tie is not scored. This makes the optimized event-set identical to
the subsequently materialized `distance <= threshold` set and preserves stable,
deterministic behavior within tie groups.

The threshold search code remains `log(|V_s|)`. The topology null and retained
component root code continue to use the global graph size `N`.

Guarded Gamma ambiguity confirmations now disable split-warm continuation. Every
confirmed candidate order therefore receives an independent cold start. Ordinary,
unguarded component searches retain their previous split-warm behavior.

Behavior can change only when either:

1. the former winning prefix ended inside an exact core-distance tie; or
2. `mdl_gamma_ambiguity_confirmation` was activated.

## Version decision

Use version **0.2.4** for the corrected optimizer and its canonical artifacts.
Existing `results/published/v0.2.3` manifests already identify a materially
different implementation and optimizer hash. Reusing 0.2.3 would assign the same
version to two behaviors that can produce different model selections, core masks,
labels, runtimes, and metrics.

If an immutable submission must retain the text “0.2.3,” it should be labeled
explicitly as the **0.2.3 submission snapshot** and pinned to an exact Git commit
and `optimization.py` hash. This is a provenance fallback, not the recommended
release identity.
