# StrataSCAN 0.2.0-dev10 implementation report

Status: most promising 0.2.0 candidate so far; keep opt-in. The synthetic
average improves substantially, but the locked matrix is not regression-free,
so this report does not recommend replacing the public 0.1.2 estimator yet.

## Frozen algorithm

`stratascan.optimization.OptimizationStrataSCAN` now follows one direct path:

1. Build a sparse 32-nearest-neighbour graph.
2. Form shell-volume observations at ranks 4, 8, 16, and 32.
3. Fit constrained multiscale Gamma mixtures with 1--8 components on every
   row and select the component count by ICL.
4. Assign each row to its maximum-posterior Gamma component. The largest
   adjacent log-rate gap separates supported density strata from background.
5. Optimize each supported stratum's observed `d4` core radius by the exact
   graph-event description-length sweep.
6. Search the background with adaptive dyadic rank windows. A candidate must
   repay its window, root, graph, and homogeneous-Poisson Beta-boundary codes;
   there is no fixed tail percentage.
7. Process Gamma strata from dense to sparse. Edges inside an optimized source
   core radius provide DBSCAN-like connectivity. Lower-density graph Voronoi
   growth may extend existing clusters but cannot merge them.
8. Attach a non-core row only when a graph neighbour's optimized core radius
   contains it; otherwise retain noise.

The implementation stays sparse and graph-native. PCA is used only after
clustering for visualization.

## Removed controls and leakage audit

The dev10 estimator has no configuration field or runtime branch for:

- the inherited lowest-2% tail probe;
- three repeated 80/20 train/validation splits;
- assignment stability `0.80`;
- component mass `0.005`;
- posterior cutoff `0.50`;
- a 10,000-observation fit cap.

All rows participate in every Gamma candidate fit. ICL and all graph codes use
only `X`/the kNN graph. Synthetic truth labels are consumed only by the
benchmark evaluator after labels have been produced. Seed 23 was used for
criterion screening; seeds 42, 73, 101, and 151 diagnosed connectivity; the
algorithm was then frozen before the locked seeds 197 and 251 were run.

The remaining fixed values are representation or numerical controls, not
evaluation gates: graph/rank width 32, shell ranks 4/8/16/32, the 2--8 mixture
search range, three numerical restarts, and solver tolerance/iteration limits.

## Alternatives evaluated

On the seven-family development screen (`n=2,000`, seed 23, one restart, 2--8
components at screening time), the information criteria behaved as follows
relative to 0.1.2:

| Criterion | Mean macro delta | Worst macro delta | Mean pairwise delta | Worst pairwise delta |
|---|---:|---:|---:|---:|
| ICL | +0.1562 | -0.0188 | +0.2036 | -0.0573 |
| BIC | +0.1518 | -0.0149 | +0.1976 | -0.0573 |
| AICc | +0.0639 | -0.3709 | +0.1059 | -0.4435 |

ICL was selected because it retained the largest average gain while explicitly
penalizing ambiguous mixture assignments. AICc overfit badly; BIC was close but
slightly weaker on average.

Other rejected designs were:

- inherited 2% tail fallback: violates the requested unified path;
- unrestricted kNN border attachment: worst development macro delta -0.4639;
- Gamma/topology description-gain border: worst early-screen macro delta
  -0.1197;
- topology-only background components: mistakes the locally connected kNN
  graph of uniform noise for cluster evidence;
- mutual-4NN connectivity: severely fragments continuous manifolds;
- connectivity restricted to the first four neighbour slots: ignores the
  optimized epsilon and fragmented moons/rings;
- manual Gamma background cuts: truth-optimal cuts were not selected by the
  unsupervised description gain, which increased monotonically as background
  was relabelled signal.

## Runtime evidence

The locked `n=5,000` matrix records graph construction separately and reuses
the same graph for the paired estimators. Median end-to-end time was 6.13 s for
dev10 and 7.11 s for 0.1.2; the median paired ratio was 0.91. These fits ran in
one process with 0.1.2 first, so they are useful paired engineering timings but
not isolated-process publication measurements.

A current-version scaling check at `n=20,000`, seed 197, all seven families,
and three Gamma restarts is in
`results/runs/optimization_dev10_runtime_n20000_seed197/`. Median times were:

| Stage | 0.1.2 | dev10 | Ratio |
|---|---:|---:|---:|
| graph construction | 0.87 s | 0.87 s | 1.00x |
| fit after graph | 14.30 s | 28.87 s | 2.02x |
| end to end | 15.32 s | 29.84 s | 1.95x |

The per-family end-to-end ratio ranged from 1.75x to 1.97x. Dev10 took
20.24--48.49 s per 20k dataset, versus 11.60--25.97 s for 0.1.2. Thus the 5k
result does not extrapolate: once `n` exceeds the old 10,000-row cap, fitting
all rows for every ICL candidate becomes the clear runtime bottleneck.

## Remaining drawbacks

1. The locked suite is not condition-wise regression-free. Moons seed 251 is
   the worst macro condition (-0.0619), and overlapping-density remains less
   reliable in pairwise F1.
2. The largest Gamma rate gap can underselect signal when cluster density
   overlaps the background density continuum. This is visible in the
   overlapping-density case and cannot be repaired by a truth-tuned cut.
3. Gaussian-overlap noise F1 falls because the stricter local-radius border
   rule leaves about four to eight additional percentage points as noise while
   greatly improving cluster identities.
4. Full-data mixture fitting removes the cap but requires `O(nK)` temporary
   responsibilities. At 20k it is already about 2x slower end to end than
   0.1.2. Million-point runtime and peak memory remain unvalidated for dev10.
5. The current optimization combines ICL model selection, exact per-stratum
   event sweeps, and coded background activation; it is not a single globally
   solved objective over every decision.

## Recommendation

Keep dev10 as the leading opt-in 0.2.0 research candidate. It satisfies the
requested architectural and magic-number-removal goals and produces large
average synthetic gains, but do not claim zero regressions or promote it until
the density/background split and strict local border recall are improved on a
new development set and then rechecked on fresh locked seeds.
